Fixes a clipboard image preview path found in a WindowSill crash report. The previous version read native clipboard content from an image binding getter during layout. The keyboard hook also ran on the UI thread, so UI stalls could delay keyboard events.

## Changes

- Image bindings return cached thumbnails. Clipboard reads and thumbnail decoding run outside layout on background workers.
- The Win+V hook has a dedicated thread and message loop. Ordinary keys and injected input pass through without shortcut processing.
- Clipboard notifications are coalesced, and refreshes retain existing controls and popup anchors.
- Unavailable clipboard entries are skipped so other entries can still refresh.

## Install

Requires Windows 11 and WindowSill 1.0.3 or newer, with Windows clipboard history enabled.

1. Disable the official Clipboard History extension in WindowSill Settings, under Manage Extensions.
2. For an earlier sideloaded fork, uninstall its extension package and restart WindowSill first.
3. Download `WindowSill.ClipboardHistory.NoLimits.0.10.1-unlimited.2.wsext` below, double-click it, and accept the installation prompt.
4. Enable Clipboard History No Limits if needed.

The encrypted history folder remains the same. Update checks do not install packages automatically.

## Validation

All 50 regression tests passed, including notification bursts, large Unicode text, image dimension bounds, and gameplay key pass-through. A native probe passed 32 concurrent hook startup and shutdown cycles without generating keyboard input. The package builds without warnings or errors and was loaded in WindowSill 1.0.3.

A full gameplay session has not been tested after the fix. This remains a prerelease.
